# Local sample

The whole flow on your own machine, with Docker standing in for the cloud. No account needed.
Requirements: Docker Desktop, OpenTofu, Git Bash (Windows) or any shell.

```bash
bash scripts/local.sh up        # ~10 minutes the first time
bash scripts/local.sh status
bash scripts/local.sh password  # Grafana admin password
bash scripts/local.sh down      # remove everything
```

| What | Where |
|---|---|
| App | http://localhost:8080 |
| Grafana | http://localhost:3000 (user `admin`) |
| Prometheus | http://localhost:9090 |
| Alertmanager | http://localhost:9093 |

What is the same as in the cloud version: OpenTofu provisions and writes the Ansible inventory,
Ansible configures, the image is built and Trivy-scanned, Helm deploys the same chart, and the
same monitoring stack, dashboards and alerts are installed by the same scripts.
What differs: the nodes are K3s containers instead of EC2 instances, so the host-hardening
Ansible roles (SSH, UFW, disks) do not run; `ansible/local.yml` does the cluster-level part.

Commands below that use `kubectl`, `helm`, `ansible` or `sops` run through the toolbox container:

```bash
tb() { ENV=local TOOLBOX_NETWORK=container:k3s-local-server-0 ./toolbox.sh "$@"; }
```

## 1. OpenTofu

```bash
cd infra/environments/local
tofu plan                 # "No changes": real state matches the code
tofu state list           # every resource tofu manages
tofu output               # node names and URLs
tofu apply -var agent_count=2    # add a node: plan shows exactly one container to add
```

After adding a node, run step 2 again and watch the new node join and get labelled.
`ansible/inventories/local/hosts.yml` is generated by tofu - open it to see the hand-off.

## 2. Ansible

```bash
tb sh -c 'cd ansible && ansible-playbook -i inventories/local/hosts.yml local.yml'
```

Read the `PLAY RECAP` line: a second run reports `changed=0`. That is idempotence - the playbook
describes a state, and does nothing when the state is already right.
The cloud playbook is `ansible/site.yml`; check it without any hosts with `tb make lint`.

## 3. Monitoring

Grafana -> Dashboards:

- **App / RED metrics** - request rate, error rate, latency of the app.
- **Node Exporter Full** - CPU, memory, disk, network per node.
- **Kubernetes / Compute Resources / Cluster** - usage per namespace and pod.
- **Logs / Explorer** - pick the `webapp-local` namespace; type in *Contains* to filter.

Prometheus -> Status -> Target health: every scrape target and whether it is UP.
Prometheus -> Alerts: all rules; `Watchdog` always fires (it proves alerting works).

Make an alert fire:

```bash
while true; do curl -s -o /dev/null http://localhost:8080/fail; sleep 0.3; done
```

`AppHigh5xxRate` turns *pending* within about two minutes and *firing* after five, then shows up
in Alertmanager. The error-rate panel on the RED dashboard goes red at the same time, and the
500s are visible in the logs dashboard. Stop the loop and it resolves.

## 4. Troubleshooting

```bash
tb kubectl get pods -A                                  # what is running, what is not
tb kubectl -n webapp-local describe pod <pod>           # events: why a pod is not starting
tb kubectl -n webapp-local logs deploy/webapp --tail=20 # application logs
tb kubectl get events -A --sort-by=.lastTimestamp | tail -20
tb kubectl top nodes && tb kubectl top pods -A          # live resource usage
```

Break something on purpose and find it:

```bash
# A pod crash: the Deployment replaces it; watch restarts and the replica panel in Grafana
tb kubectl -n webapp-local delete pod -l app.kubernetes.io/name=webapp --wait=false
tb kubectl -n webapp-local get pods -w

# A node failure: NodeDown / KubeNodeNotReady alerts fire after a few minutes
docker stop k3s-local-agent-0
tb kubectl get nodes
docker start k3s-local-agent-0

# A bad release: Helm waits, gives up and rolls back on its own; the app stays up meanwhile
tb env IMAGE_REPO=webapp IMAGE_TAG=doesnotexist bash scripts/deploy.sh
tb helm -n webapp-local history webapp
```

## 5. Management

```bash
tb helm list -A                                              # every release and its version
tb helm -n webapp-local history webapp                       # release history
tb helm -n webapp-local rollback webapp 1 --wait             # go back to a revision
tb kubectl -n webapp-local get hpa,pdb,networkpolicy,ingress # scaling and policy objects
tb sops decrypt secrets/local/app.enc.yaml                   # how secrets are stored
```

Network policy check - a pod in another namespace cannot reach the app:

```bash
tb kubectl run np-test --rm -i --restart=Never --image=busybox:1.37 -- \
  wget -q -T 5 -O- http://webapp.webapp-local.svc.cluster.local/
```
